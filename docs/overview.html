Autonomous UI test execution agent

A test agent that reads the ticket, drives the browser, and decides pass or fail in code

Move a GitHub issue to “Ready for QA” and the agent turns its acceptance criteria into scenarios, runs them against SauceDemo through Playwright MCP, and posts a report with logs and screenshots.

How a run goes

1 · READ

Issue reader

Fetches the issue from GitHub, or a local fixture without a token, and parses the acceptance criteria.

2 · PLAN

LLM planner

Writes scenarios, steps and assertions as JSON. A schema check rejects bad plans; one criterion left half-covered triggers one re-plan.

3 · ACT

Executor

Finds each element by its description in the page snapshot, then clicks, types or selects through Playwright MCP.

4 · JUDGE

Assertion engine

Compares expected values with the live page in ordinary code and writes the report, log and screenshots.

Why the results can be trusted

  • The LLM never decides pass or fail.It plans and picks elements. A URL, text, count, visibility or input value is checked by code against the real page. Anything the page cannot show is marked for manual review, not passed.
  • No hardcoded selectors.Steps say “the Sort dropdown”. The resolver may only return an element that exists in the current snapshot, and its answer is validated first.
  • Every loop is bounded.Step, scenario and action limits, one self-healing repair per step, one re-plan, one navigation retry. Quota errors are never retried.
  • Unsafe browser tools are blocked.Script evaluation, route changes and file upload are not on the allow-list.
  • Failures say what to do.The report gives what happened, what the page showed and the next step, and sorts the cause into application, automation, LLM provider, environment or limit.

Self-healing and the Action

Self-healing

If a step cannot find its element, the agent asks the LLM once for a repair from the current snapshot, retries, and records it in the report. A second failure is a real failure.

GitHub Action

Adding the status: RFQA label runs plan and execute on a fresh runner, uploads evidence/ as an artifact and comments the summary. Secrets exist only in the steps that need them.

Run it yourself

npm ci
npx playwright install chromium
cp .env.example .env        # set LLM_PROVIDER and LLM_API_KEY
npm run check:config        # free, no LLM calls
npm run execute:plan        # runs the saved plan, writes evidence/

Known limits

The planner prompt still holds some rules written for the cart flow, and the agent targets SauceDemo only. Browser video is not recorded; screenshots after every step stand in for it. Both are listed in TEST_PLAN.md.
